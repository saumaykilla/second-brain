# f-b-07 — Reflection and Promotion

Lane: **Person 2 — Recall (Atlas to answers and UI)** · Covers: R22

## Goal

Improve the harness only when measured evals improve.

## User-visible behavior

Running reflection proposes one harness change, reruns the evals, and keeps it only when the score improves without a precision drop. Rejections are recorded with the reason.

## Scope / out of scope

In scope:

- Reflection with the strong model over failed cases and negative feedback.
- Candidate versions and the promotion rule.
- `POST /api/reflect` and the nightly entrypoint used by `f-a-09`.

Out of scope:

- Harness Lab UI (`f-b-08`).

## Acceptance criteria

- AE5: a precision drop is rejected and the parent stays active.
- An improving candidate becomes active.

## Verification steps

1. Force a precision-lowering candidate and verify rejection.
2. Run an improving candidate and verify promotion.
3. Verify feedback is an input.
