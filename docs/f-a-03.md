# f-a-03 — Attempt Merging and the Ingest Pipeline

Lane: **Person 1 — Capture (sources to Atlas)** · Covers: R9, R10

## Goal

Run capture end to end and merge a start and a later result into one attempt.

## User-visible behavior

A captured Slack-style or web message becomes a structured decision or attempt. A later result in the same thread updates that attempt instead of creating a duplicate.

## Scope / out of scope

In scope:

- Real `ingestMessage` contract: classify, extract, merge, embed, then call `checkConditions` for decisions.
- Merge rule: same thread, or same author within the harness merge window.
- A trace record for each pipeline step.

Out of scope:

- Slack transport (`f-a-06`).

## Acceptance criteria

- A start and a result in one thread produce one attempt.
- Replaying a message is a no-op.

## Verification steps

1. Post a start then a result in one thread and verify one attempt with outcome, blockers, and evidence.
2. Verify noise is stored and creates nothing.
3. Verify embeddings exist on new records.
4. Verify each step wrote a trace.
