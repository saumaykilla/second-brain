# f-b-01 — Dead-End Check

Lane: **Person 2 — Recall (Atlas to answers and UI)** · Covers: R11–R14

## Goal

Find a failed attempt that matches a new intent, and warn only when a judge agrees.

## User-visible behavior

Pasting a plan that repeats a failed approach returns the matching dead end, blocker, evidence, alternative, hours, and confidence. A different idea does not warn.

## Scope / out of scope

In scope:

- Real `checkDeadEnds` contract: `$vectorSearch` filtered by project and outcome, graph context, then a strong-model judge.
- `POST /api/check`.
- Reads `k`, `minScore`, and the judge prompt from the harness.

Out of scope:

- Slack replies (`f-b-05`).

## Acceptance criteria

- AE1: socket.io matches WebSockets with blocker, SSE, and 14 hours.
- AE2: managed pub/sub named in the conditions does not match.
- Never returns another project's attempts.

## Verification steps

1. Run retrieval and judge tests, including tricky non-matches.
2. POST the socket.io plan and verify a match above the cutoff.
3. POST an unrelated plan and verify no warning.
4. Verify the judge can reject a high vector score.
5. Verify project isolation.
