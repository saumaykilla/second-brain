# f-a-10 — Connect Notion and GitHub, then ask over them

Lane: **Person 1 — Capture (sources to Atlas)** · Covers: R1, R14, R34

## Goal

A person connects their own Notion workspace and GitHub account, chooses which pages and repositories the project may read, and then every question on Ask is answered against that connected content with citations that open the page or file.

## User-visible behavior

On `/sources`, Connect GitHub and Connect Notion send the person to that provider to approve access. After they return, Sources lists the repositories and pages their account can see. They check the ones to share and save. Second Brain reads only that selection into project memory. On `/ask`, a question is answered from the connected pages and files, and each citation opens the source. Tokens stay on the server.

## Scope / out of scope

In scope:

- GitHub OAuth and Notion OAuth start and callback routes. Client secrets and access tokens never reach the browser.
- Per-project storage of the connection and the selected ids in MongoDB.
- Catalog of repositories and pages from the connected account.
- Saving a selection syncs those sources into `source_chunks` (chunked, embedded) and removes chunks of sources that were unchecked.
- `/api/ask` retrieves from the connected chunks in the same project and cites them alongside attempts and decisions.
- A not-configured state when the OAuth app ids are missing.

Out of scope:

- Pages or repositories the person did not select.
- Webhook-driven incremental sync. Saving the selection re-reads the sources.
- Changing `lib/types.ts` or a lane contract. New collections live behind `lib/sources/`.

## Acceptance criteria

- Connect GitHub builds a GitHub authorize URL that includes the client id and not the client secret. Same for Notion.
- A callback stores the access token on the project and the response to the browser does not contain it.
- The catalog lists repositories and pages from the connected account.
- Saving a selection of one repository does not store files of an unselected repository. Same for one Notion page versus an unselected page.
- A question whose answer is in a connected file returns that file as a citation with a URL, and the answer is not marked unsupported.
- Results are filtered by project id.

## Verification steps

1. Run the sources tests: OAuth URL, chunking, GitHub path filter, Notion title and text extraction, and, with `MONGODB_URI` set, the grant-and-ask integration against mocked provider APIs.
2. Confirm access tokens and client secrets are absent from API responses and from `app/`, `components/`, and `lib/` client code.
3. Open `/sources` and use Connect GitHub and Connect Notion. Without OAuth app ids the page says sign-in is not configured; with them the browser reaches the provider login.
4. Save a selection and confirm the synced list shows only the checked sources.
5. Ask a question on `/ask` that is answered by a connected file and open the citation.
